# 内置 reference skill 场景测试

使用 deepseek-flash 的独立子 agent，无 skill 时只读取真实工具契约，再给出两营补员且人类并发改名/加班的场景；未执行真实工作区写操作。

## RED 基线

基线正确选择多文档事务、保留名字与直属人数，但暴露了两个具体缺口：

1. 先从 workspace 记 `SEQ0`，然后 `orbat_changes {since:SEQ0}` 希望查到此前人类改名和加班。这会漏掉已经包含在当前 sequence 内的变化。
2. 预览若截断，提出再用同一个根节点聚焦，不能减少范围，因此不解决截断。

另有不确定项：personnelMax语义、导出是否自动导入站点、空闲AI是否因人工变化自动运行。

## GREEN 指导

skill 明确首次从since0读、cursor只推进到实际消费的nextCursor；截断应聚焦更小子树而非同根；人员为直属、上限0未指定、导出仅文件、闲置不自动唤醒。原子与冲突规则由程序强制，不依赖文档提醒。
