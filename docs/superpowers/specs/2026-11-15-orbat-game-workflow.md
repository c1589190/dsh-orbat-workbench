# 编制协作工作台：文游录入与完整资料设计

> 用户决定：选择 B——工作台保留无损原生数据，同时支持原 Army_Editor 兼容文件；开始实施，善用 DeepSeek Flash 子 Agent 并采用 SimulatorMosire 责任区制。用户原话：“skill问题，很显然你应该修改本插件推出的编制创建/修改skill”“工具问题，全！部！支！持！”“录入工作流”“这是我要用来打文游的编制图，不要加上示意！”

## 目标与非目标
- 主图正常显示部队名称，不把“示意”“推定”放进名称；证据状态保存在独立资料中。
- 历史资料不足时可以使用有来源的同期类型编制或有解释的推定，不能冒充某师某日的事实；未知不能当真实0。
- 网页和工具共享同一应用与事务核心。支持字段级状态与来源、直属/合计、批量人员装备、模板与复制、预览差异、目录、兼容导入导出。
- 不宣称美军类型手册是1988年的苏方实有记录，不凭用户未提供的证据伪造完整实有数据。公共 Army_Editor 不实时同步工作台。

## 现状事实
- `src/model.js` 现将缺失人数归0、缺失装备归空；`stats` 将直属值递归求和。`src/render.js` 另有汇总逻辑，须同步避免假精确。
- `src/workspace.js` 基于 revision 和进程内队列原子提交；无跨进程锁。`src/application.js` 是网页和工具的共同分派层。网页批量只支持人数增量/根备注，装备是 JSON 字符串。
- 原站兼容导入目前拒绝非空自定义装备表；上游对扩展元数据保存情况未知，不得假定会无损保留。
- 当前项目不是 Git 仓库；既有 `docs/progress.md` 明确选择在当前目录开发，不伪造分支或提交。运行 Host 已打开共享数据，禁止在该目录启动第二个同数据目录 Host 或以脚本修改 `.workbench`。

## 目标运行和数据契约
1. 读当前文档和 revision，保留全部现有 id、字段、用户修改和历史。对旧字段不推断0含义：legacy 数值保留，旧0若无明确证据则标记歧义，不凭空转已知零或未知。
2. 在保留 Army_Editor 数值字段的同时，工作台必须可表示每个直属人数、装备条目数量及装备清单完整性的 `actual`、`standard`、`estimate`、`unknown`、`legacy-ambiguous` 状态。`actual` 的数值可以是0；`unknown` 不参与已知合计。资料可携带日期、标题、URL、页码、方法、备注；字段级数据与操作 actor 分离。具体可用带版本命名空间的 node `custom` / item 安全扩展实现，但必须防止覆盖现有 custom 字段并验证。
3. 统计返回已知小计、未知和推定覆盖情况以及非重复的直属与后代汇总；来源总数单独存储，不自动拆分。旧调用保留原数值接口，新增明确的完整性字段；网页和渲染不能把不完整合计当精确实数。单位名称保持原样。
4. 操作统一为确定的服务端计划：按文档/子树/兵种/层级/名称/装备/状态选择；预览列出节点 id、revision、before/after、影响数、合计及风险；提交冻结的节点集、操作与所有源/目标 revision，变化则 CONFLICT，禁止静默重算覆盖。支持批量人数赋值/增减/状态、装备项增删改、资料合并、子树克隆与模板批量命名。禁止无意覆盖未触及装备或 custom 字段；新增节点 ID 独立。
5. 内建可编辑装备目录含名称、别名和安全 JSON 性能数据，归工作区所有；导入导出须保留，不因业务数据误执行代码。提供可版本化的完整原生备份格式（含所选文档、资料、目录、模板；独立于原站格式）和 `mil-org`/`mil-bundle` 兼容导出。兼容导出无法表达的未知、资料、目录或地图等必须返回可读损失报告，不静默承诺往返无损；实际原站能力须测试。
6. 网页提供结构化装备表与搜索、人员和来源状态、直属/合计、模板/复制、子树筛选、批量预览/提交；AI工具暴露同等数据操作。图正常名称不出现人为加的示意标签。现有修订冲突和未保存草稿保护不可回退。
7. 修改内置 `orbat-workbench` skill：面向文游默认完整交付，资料不足合理有依据推定；名称不写示意；引用字段级证据；使用新批量能力和冲突保护。先进行无新指导基线、再测更新后行为。
8. 最后重新读取共享工作区的近卫第4师及 changes，只针对由本会话创建的示意前缀且未被人类改过的节点进行安全、可回滚的字段级清理；记录来源，并按1988口径填充能合理估算的人员装备。遇冲突重读后重建，永不覆盖人类修改。保留原始师文档。

## 安全与验收
- 任一事务非法、过期、多文档部分失败必须不提交；预览无副作用；跨文档/模板复制同时校验源、目标修订。
- 历史0歧义、已知0、未知、部分清单、推定、装备目录重名/别名冲突、上下级汇总、防原型污染、数据往返、超过查询200和事务1000边界均需负向测试。
- 工具和网页经同一服务；覆盖分页、增量未知处理、草稿冲突、人类并发编辑和预览一致性。
- 每个责任区先有独立测试 Agent 建立可执行RED，再由唯一生产代码写入 Agent 修复；责任区结束控制方复核测试与实物，风险点派只读评审。用户要求使用 DeepSeek Flash；不同时派多个写代码 Agent。
- 本地完整 `pnpm test`、`pnpm run check`、客户端 `pnpm run build` 及相关真工具/图片校验；不把代码测试当成现有DSH GUI实测。源码更新是否进入已运行 Host 必须单独验证；不得重启或另开替代服务冒充。
