# 编制协作工作台 Demo 设计

状态：用户要求直接交付实验性 demo；不是生产版或对原网站的无侵入实时同步。

## 目标

在当前目录编写独立 DSH bundle。人和 AI 通过同一操作层编辑多份编制；带修订检查、原子批量操作和可追踪差异；产出 SVG/PNG 预览与 Army_Editor 1.8.0 可导入 JSON。安装后自动注册使用技能，模型可发现并按需加载。

## 方案与范围决定

- 纯 skills + 文件：不能满足双向协作、冲突保护与图像预览，排除。
- 共享 Host 工作区 + DSH 原生 Client 页面 + 工具：采用，避免复制上游编辑器及授权不明资源。
- 改造/注入第三方公共网页：留待后续，需要显式 bridge，demo 不承诺与未改造 GitHub 网页实时同步。
- 用当前空目录直接开发（用户明确指定），不创建 worktree、不修改 DSH 源码、不启动替代服务器。
- 图像使用自行实现的树布局、MIT milsymbol 符号和 PNG 光栅化，属于产品功能，不作为 DSH UI 截图的替代。

## 数据与协作

单个工作区包含 documents 与单调 sequence 的 changes；各 document 各有 revision，节点有内部稳定 id。导入时生成 id，导出剥离 id。数据保存于配置的 dataDir 中，整个工作区单文件原子落盘，服务内串行事务。

修改通过 transaction({edits:[{documentId,expectedRevision,operations}],summary},actor)。多编制在一次事务内全成或全败。过期 revision 返回 conflict，不自动重放、不盲覆盖。每次成功编辑记录 actor（human/ai）、summary、各文档修订前后值、节点级字段 before/after。保留可查询历史与截断标志。网页使用事件订阅同步最新状态；正在填写的表单保留草稿并显示远端更新，保存仍用打开表单时的 revision。

AI 工具提供工作区状态/多文档读取与查询/事务/导入/导出/渲染/变更读取。人类 UI 调用同一个 Host dispatch。动态提示仅提供有界工作区状态和近期人工变化，引导模型重新读取，绝不把存储文件中的任意内容当指令。空闲 AI 不被每次人类键入自动唤醒。

## 界面

DSH sidebar 主面板入口：编制协作。左侧多编制列表与复选框，中间渲染预览与节点树，右侧节点字段编辑和带来源的变更历史。提供创建、导入、复制、增删移动节点、批量事务、下载 JSON/PNG。数据刷新使用 SSE，不轮询。页面清晰标明实验性、原网站导出边界、当前 revision、冲突、未保存草稿。

## Skills

内置一个 reference skill（orbat-workbench），安装时注册独立 provider，不覆盖用户全局 skill-filesystem 配置。内容包括发现工具、读取当前修订、先读人工变化、用事务修改、冲突重读、预览后交付、人数为直属统计、原站导入流程。以无 skill / 有 skill 场景验证使用路径。

## 验证

Node 原生测试覆盖多文档事务、原子失败、并发修订、删除根/循环/无效数值与路径、历史来源与差异、持久化重开、兼容导入导出、渲染中文/转义/大树有界输出。安装通过 plugin_manager，在当前 http://127.0.0.1:3080 查询 Host/Client 注册并验证 HTTP 交互。不另开服务器、不从个人浏览器提取认证。

没有浏览器控制工具时不宣称已完成 DSH UI 实际视觉验收；用真实产品渲染结果展示图片，并如实写明 UI 未验证项。
